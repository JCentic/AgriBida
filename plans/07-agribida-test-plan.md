# AgriBida Test Plan

| Test Case ID | Feature | Test Scenario | Input or Action | Expected Result | Actual Result | Status |
|---|---|---|---|---|---|---|
| TC-01 | Produce Bidding System | Submit a successful bid for an open listing. | As Buyer, open an **Open** Tomato listing in Nueva Ecija with 150 kg available. Submit ₱38 per kg for 100 kg with the message “Can collect on September 10.” | The system accepts the valid bid, saves it under the selected listing, and makes it visible in the farmer’s bid-comparison view. |  |  |
| TC-02 | Produce Bidding / Price Comparison | Submit a positive bid below the sample market low price. | For a Tomato listing with a sample market range of ₱30–₱42 per kg, submit a bid of ₱25 per kg for 100 kg. | The bid is accepted because it has a positive price and quantity. The bid-comparison view clearly shows the ₱25 offer beside the sample ₱30–₱42 market-price range for the farmer’s decision. |  |  |
| TC-03 | Listing Validation | Attempt to create a listing with missing required information. | As Farmer, leave the location and availability date blank, then select Save. | The system does not save the listing and shows clear validation messages for the missing required fields. Valid entered values remain visible for correction. |  |  |
| TC-04 | Bid Validation | Attempt to submit an invalid bid. | As Buyer, enter an offered price of `0` and requested quantity of `-10` for an open listing, then select Submit Bid. | The system blocks submission and shows clear errors stating that price and quantity must be positive numeric values. |  |  |
| TC-05 | Bid Status Validation | Attempt to bid on a selected or closed listing. | As Buyer, open a listing whose status is **Selected** or **Closed** and try to submit a bid. | The system blocks the bid and informs the buyer that bids can only be submitted or updated for Open listings. |  |  |
| TC-06 | Buyer Verification and Reputation | Display a verified buyer’s trust information. | Open the profile or bid card of **Metro Fresh Produce** with status **Verified Buyer**, rating `4.6`, review count `12`, and sample feedback. | The interface displays the buyer name, Verified Buyer label, 4.6 rating, 12 review count, and sample feedback. |  |  |
| TC-07 | Buyer Verification and Reputation | Display a pending or unverified buyer’s trust information. | Open the profile or bid card of a buyer with status **Pending Verification** and a sample rating. | The interface displays the Pending Verification label clearly, together with the buyer’s available rating, review count, and sample feedback. |  |  |
| TC-08 | Buyer Verification and Reputation | Confirm that buyer ratings appear during bid comparison. | As Farmer, view bids from two buyers with different sample ratings, such as `4.6` and `3.8`. | Each bid shows the correct buyer rating and verification label, allowing the farmer to compare credibility information with offered prices. |  |  |
| TC-09 | Price-Transparency Dashboard | Display matching sample market-price data. | Filter the dashboard by produce **Tomato** and location **Nueva Ecija**. | The dashboard displays the matching sample record, including low price ₱30, average price ₱36, high price ₱42, and unit kg. |  |  |
| TC-10 | Price-Transparency Dashboard | Filter using a produce and location without a sample price record. | Filter the dashboard by a produce-location combination not included in the sample data. | The dashboard does not display misleading prices and shows a clear no-data message. |  |  |
| TC-11 | Bid Ownership Validation | Attempt to update another buyer’s bid. | Sign in as Buyer B and attempt to open or update a bid that belongs to Buyer A. | The system blocks the update and shows an appropriate unauthorized-action message. |  |  |
| TC-12 | Registration Validation | Submit the Create Account form with missing required fields. | Leave Full name, Email, Location, Role, and the farm/business name field blank, then select Create Account. | The system does not create an account and shows a clear inline error under each missing field. Previously entered valid values remain visible. |  |  |
| TC-13 | Registration Validation | Register with an email already used by another account. | Submit the Create Account form using the seeded email `maria.santos@agribida.test`. | The system blocks submission and shows "An account with this email already exists." next to the Email field. |  |  |
| TC-14 | Registration Validation | Register with a weak password or mismatched confirmation. | Enter a password under 8 characters, and a Confirm password value that does not match. | The system shows "Password must be at least 8 characters." and "Passwords do not match." beside the respective fields, and does not create the account. |  |  |
| TC-15 | Registration / RBAC | Successfully register as a Farmer or Buyer. | Submit the Create Account form with valid, unique details and role Farmer (or Buyer). | The system creates the user record and a matching farmer (or buyer, defaulting to Pending Verification) profile, signs the new account in automatically, and confirms the role-appropriate destination. |  |  |
| TC-16 | Authentication | Sign in with an incorrect password. | Enter a registered email with the wrong password and select Sign In. | The system shows a generic "Incorrect email or password." message, clears the password field, and does not reveal which field was wrong. |  |  |
| TC-17 | Authentication | Sign in with valid credentials. | Enter a registered account's correct email and password and select Sign In. | The system signs the user in and confirms the account's role without the user selecting a role directly. |  |  |
